# Opportunity workspace

Stage-filtered cursor lists, deep-linked details and bounded activity history use generated API
contracts and organization/session-scoped query caches. Existing ledger tokens are preserved.
Commands use RHF/Zod, reason, explicit confirmation, pending-disabled inputs and stable retry keys.
The backend decides every transition; read-only/terminal views hide commands. No manual win or
reopen is offered. Lost opportunities preserve quote evidence but cannot accept quotations later.

Lost reasons default to confidential independently of timeline entries. The shared text-review
form uses the CRM source endpoint and refreshes detail/history after review; original domain read
permission and profit.read are both needed for review. Identifying names remain visible.
